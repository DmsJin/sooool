# DFJK 实时视觉策略实验结果

验收完成：冻结策略通过真实 `gpt-6.1-sol / ultrafast / low` API，在原生音频时钟、原速 1× 下连续三局达到 **100% 加权准确率、零漏键、零空按**。

范围是当前环境的《Never Gonna Give You Up》**30 秒官方试听片段、难度 1、52 个音符**。没有验证完整歌曲或其他谱面。

## 真实 API 验收

| 连续局次 | PERFECT | GREAT / GOOD / MISS | 得分 | 准确率 | 请求数 | 最大音频时钟漂移 |
|---|---:|---|---:|---:|---:|---:|
| 1 | 52 | 0 / 0 / 0 | 52000 | 100% | 252 | 86 ms |
| 2 | 52 | 0 / 0 / 0 | 52000 | 100% | 243 | 11 ms |
| 3 | 52 | 0 / 0 / 0 | 52000 | 100% | 249 | 69 ms |

三局共有 744 次已完成、已结算的 API 响应，全部返回指定模型与 ultrafast 档位，推理配置 low；没有请求超时或预算中断。API 完整响应延迟最小 0.739 s、中位数 1.012 s、P95 1.553 s、最大 4.327 s。慢响应仍保留在记录中，迟到时由其他已到达的视觉决策提供补救。

逐条核验了 156 次实际执行按键、三个结果页、每次请求身份、截图尺寸、策略源文件 SHA-256 和音频 SHA-256。重新计算原始时钟日志，确认 `playbackRate` 始终为 1，游戏中没有暂停，音频与 performance 时钟单调前进并在完整 30 秒后进入结果页。没有等待模型时暂停或推进原生时钟。

原生验收在用户提供的 SSH 机器运行。使用默认绘制频率，未使用本地诊断时尝试的 30 FPS 限制。Headless 默认静音输出；同一段音乐的原生媒体时钟正常运行。录屏为无声 WebM。

## 策略和因果边界

- GPT 接收当前真实画面的顶部 200 像素，只返回最上方两个蓝色音符的 `[lane, integer_y]`。裁剪是固定矩形，未使用自动音符检测、阈值识别或谱面查表。
- 执行器根据公开几何换算时间：`until_hit_ms = (601 - y) / 601 * 1800`，再加上该画面实际渲染时的原生音频时间。
- 目标观察间隔 100 ms，最多 20 个付费请求在途；实际采样数量受通信开销影响，以上表和逐次日志为准。
- 稀疏队列保留未被新画面提及的按键，只更新同轨道附近的同一目标；新旧响应按目标分别判断，临近 50 ms 的已排按键保留。
- 目标迟到不超过 55 ms 时在当前真实时间立即按下，由游戏的原始判定计分；更旧的目标丢弃。不存在回溯按键。
- 迟到响应仍等待其用量结算，不因超过 1.75 s 的预期可用窗口立即取消付费传输。传输总时限 60 s；若发生未知费用则保留预算预留。

最终模型输入仅包含固定短提示词与截图。原始谱面、`rhythmDebug.notes` 和评估器对象没有进入模型输入或动作生成。可信评估器只用于计分和故障分析。无 API 的 oracle 对照用于检查浏览器时钟，未计入 GPT 成绩。订阅调用使用隔离观察目录、强制 ChatGPT 登录模式，无 API 回退；审计到的模型工具事件为零。

## Profiling 和订阅迭代

所有付费 profiling 都使用 Responses API 严格串行：上一请求完成后才发下一请求，并校验服务端返回的模型与档位。

| 串行测量 | 样本数 | 最快 | 中位数 | 观测最大值 |
|---|---:|---:|---:|---:|
| 原始完整画面提示词 | 8 | 0.989 s | 1.206 s | 1.399 s |
| 完整画面短提示词 | 8 | 1.053 s | 1.539 s | 2.706 s |
| 本地顶部裁剪短提示词 | 8 | 1.032 s | 1.280 s | 1.752 s |
| Ubuntu 顶部裁剪短提示词 | 8 | 0.950 s | 1.219 s | 2.847 s |

这是小样本实测，不能据此保证 P99。最初板面测量中另有一次 53.872 s 尾部响应，保留在旧记录中。顶部两音符的初次 128-token 试验在第四次请求因包含推理的输出达到上限而失败，随后改用 512-token 上限；失败和原始源文件均保留。

订阅模拟使用真实 GPT 图像决策，把实测 API 延迟采样为虚拟响应到达时间。订阅推理可能花几十秒墙上时间，模拟只在对应因果时间揭示答案。它不等同于实时吞吐，也不作为最终原生 API 验收的替代。

| 完整模拟组 | 三局得分 | 漏键数 | 结论 |
|---|---|---|---|
| r1 完整提示词 | 52000 / 51000 / 52000 | 0 / 1 / 0 | 未满足零漏键 |
| r1 future 提示词 | 52000 / 51000 / 52000 | 0 / 1 / 0 | 未满足零漏键 |
| r1 compact 提示词 | 52000 / 52000 / 52000 | 0 / 0 / 0 | 原始较快延迟分布通过 |
| r2 临近按键保护 | 52000 / 52000 / 52000 | 0 / 0 / 0 | 原始较快分布通过 |
| r3 最新完整画面延迟 | 35000 / 44000 / 36000 | 17 / 8 / 16 | 长尾条件失败 |
| r5 裁剪与稀疏合并 | 51000 / 52000 / 52000 | 1 / 0 / 0 | 两局通过，一局失败 |

r1 有三局在进程意外中断后用验证过的原决策前缀恢复；原记录和恢复记录分开保存，未重跑已完成局。r5 的一局在最后阶段另有一次订阅模型请求超时，记录未删除。

r5 的那次漏键经过完整因果追踪：六个连续画面都正确识别该音符，但恰好全部抽到 2.538–2.847 s 延迟，全部迟到；该观察窗口没有容量丢帧。因此不能声称策略保证通过任意长尾采样。最终连续三局真实 API 验收是独立实测，达到用户约定的验收目标。

每组三局订阅测试最多 24 个真实 worker 并行。早期完整一组约 12 分钟；r5 三局墙上耗时约 739 / 629 / 623 秒。订阅 Fast (`priority`) 两次独立探测为 10.55 s 和 4.31 s，没有显示稳定收益，最终策略未切换。

## 浏览器时钟故障和隔离

第一次本地真实 API 局只有 16 PERFECT、36 MISS，最大原生时钟漂移 2.800 s，未通过。无 API 对照也失败，证明仅等待 API 不是全部问题。关闭其他实验浏览器后的本地对照仍出现 3.880 s 漂移；取消默认静音或限制绘制频率仍不足以恢复可靠时钟。

迁移到授权 SSH 机器后，同一游戏、同一音频和原生 1× 时钟的无 API 对照为 52 PERFECT、零漏键，最大漂移 58 ms；带视频时再次通过，漂移 57 ms。正式三局随后在该机器完成，未放宽漂移或计分要求。
