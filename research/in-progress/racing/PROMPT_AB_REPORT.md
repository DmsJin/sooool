## 实验方法

- 固定 `gpt-6.1-sol / low / ultrafast`，通过真实 ChatGPT 订阅认证调用，无付费 API 回退。
- 从原有 5 倍慢放完整比赛的三个 seed（101/111/121）中各选 8 个观测，按比赛时间分层抽样，覆盖两局。样本取自已成功轨迹，结论不代表所有困难或失败状态。
- 每对使用完全相同的 task prompt、图像和动作格式；核验图像 SHA256。预先随机打乱样本顺序和 A/B 先后次序，两种先后顺序各 12 对。
- 串行交错执行，两个长驻客户端各预热 1 次，预热不计入结果。共 50 次订阅模型调用。
- 完整耗时包括账户额度读取、创建线程、模型返回和取消线程订阅；一次性进程启动另记。缓存没有强制禁用，实际缓存 token 如表。
- A 是已有赛车控制器：此前已经用短的赛车 `baseInstructions` 替换了默认 coding prompt，并关闭部分能力。它不是全默认 Codex。
- B 使用用户提供的非空 `system.txt`，以 `model_instructions_file` 加载；关闭额外说明块、skills、Apps、plugins、MCP、shell、搜索、浏览器和多 agent 等无关能力；保留 read-only sandbox 和 never approval。
- B 使用独立、权限受限的临时 `CODEX_HOME`，仅复制当前订阅登录文件，不带全局 AGENTS 或配置；结束后删除。原账户配置未修改。
- 远端版本 `codex-cli 0.162.1` 不支持 `--ignore-user-config`，以独立 CODEX_HOME 实现配置隔离。`--strict-config` 验证通过。旧 `tools.view_image` 配置不受支持，改用 `features.view_image=false`。

输出合法率不是决策准确率；本实验没有为每张图像指定唯一正确动作。另用相同状态、相同原始采样 API 延迟执行 1 游戏秒的动作分支，检查局部推进和碰撞，其结果见证据中的 `quality_summary.json`；这不等于完整比赛胜率或真实 API 验证。

48 个分支均通过原始观测图像哈希校验。现有版 / 精简版的平均推进分别为 2.882 / 2.855 米；出现墙体接触的分支为 3/24 / 2/24；两版都没有障碍物接触或新增裁判警告。推进与接触指标各有细小变化，没有足够证据认定驾驶质量改善或恶化。
