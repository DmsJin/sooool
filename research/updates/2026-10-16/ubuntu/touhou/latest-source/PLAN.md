东方辉夜 Lv.1 · Sol 实时通关实验计划

本轮为计划与只读勘察；未发起付费模型请求，也未启动订阅批量实验。用户已授权本任务累计 API 消费不超过 USD 30、订阅迭代、并发策略和远端实验。文档中的阈值为本次建议，PDF 是参考方法，不自动变成本次执行指令。

1. 目标与验收

最终目标：gpt-6.1-sol 根据连续真实游戏画面，在原速下通过真实 API 控制当前辉夜 Lv.1 环境，终局 status=won。存活至 60 秒的 survived 单独报告，不算击破通关。

先取得一次完整真实 API 通关，再争取固定协议的三局稳定验证。网站默认引擎 seed=1 必须包含；开发用引擎 seeds 2/5/6，API 留出用 7/8/9，按预先确定顺序运行，所有尝试都报告。最低演示里程碑为默认 seed 的一次原速 API 通关；稳定性目标为预定三局全部通关，不能用最好的一局替代成功率。

游戏逻辑、难度、HP、弹道、碰撞、初始残机和符卡数冻结。限时 3600 逻辑帧、60 游戏秒；前端开场及切卡演出暂停逻辑时钟，另记演出时间和墙钟时间。若先在慢速下成功，只标注慢速模拟成功，继续争取原速，不能当成最终目标已完成。

3. 观测、动作和真实时钟协议

玩家模型看到当前原作素材前端的游戏画框（弹幕区+HUD），1–3 张带逻辑帧号的截图；可附当前已执行按键和有限已生效动作历史。默认视觉输入，不附隐藏 seed、谱子/未来弹道、精确实体状态或分析器计算的安全路径。离线诊断可读状态，但不反向注入在线决策。

复用原引擎和原前端渲染器，提供两个时钟适配器：离散事件模拟与真实 wall-clock。真实模式推进不等待模型或截图；截图捕获异步，使用实际渲染帧时间戳。记录捕获、提交、首 token、完整合法命令、实际应用时间，以及相应游戏帧。

现有浏览器 requestAnimationFrame 有 100ms 累积截断且失焦会暂停。实验适配必须监测丢时、失焦、暂停和实际推进速度，不能让截图负载把游戏降速后仍称原速。真实运行的开始/切卡演出保留且独立记账；等待模型不增加演出或暂停。

每条输出为有界按键动作或短 action chunk。先测试 [move,shoot,focus,bomb,duration] 的紧凑编码；duration 候选为 6/12/24/48 逻辑帧，chunk 长度候选 1/2/4。具体初值由 profiling 和基线确定，不一次做全笛卡尔积。

明确冻结动作规则：较新观测的有效响应覆盖较旧计划；旧响应不得反向覆盖已执行的新观测；新 chunk 替换旧 chunk 的未执行后缀；到期释放移动，射击/低速保持按已声明规则执行；X 必须正确释放后才可再次触发。模型可见已提交且已返回的计划，不能看到尚未完成的答案。

只允许解析、合法范围校验、按键转换、超时释放、陈旧响应过滤等执行器行为。所有影响走位和放符卡的策略决定来自 Sol。若引入视觉提取器、自动避弹器或安全控制器，须成为独立的辅助条件，不能混入视觉 Sol 主成绩。

4. 第一阶段：仅用 API 串行 profiling

模型先沿用旧实验的 gpt-6.1-sol / low，测速优先 Ultrafast，连接复用。可串行比较持久 HTTPS 与 WebSocket；任何时刻全 profiling 只有 1 个在途请求，模型返回后才发下一条。不启动并发测速或并发试玩冒充 profiling。

输入来自东方实际前端：稀疏/密集弹幕、Boss 移动、符卡和坠机画面。分别检查单帧与三帧、精简动作与短 chunk、图片细节和有限历史。先少量检查画面可辨识、模型身份/tier、usage 和价格，再对候选各做约 20–30 个串行样本，最终选择做额外样本；总数受阶段预算控制，不承诺固定请求数。

同时记录：冷/暖连接、准备/编码时间、TTFT、完整合法动作时间、总返回时间、输入/缓存/输出/reasoning tokens、无效动作率、费用。报告 min、P10/P50/P90/P95 和样本量，最小值只说明观察到的最快值，不当作稳定可达到值。主 profile 使用与部署相同协议的完整合法动作延迟，而非首 token。

保留原始逐请求样本和配置哈希。图像数量、历史、输出长度、模型 effort、tier 或传输改变，需要新的 profile 身份。最终冻结 policy 后串行复测实际请求形状；旧 Asterix 的并发 8 校准与 224px 图像数据不直接当作东方 profile。

5. 第二阶段：订阅决策＋抽样延迟开发

通过已有原生订阅接口真正让 Sol 看图给动作；API key 仅由独立付费 runner 在内存使用，订阅进程不继承 key，也不允许失败后自动转 API。

每次模拟提交按对应 profile 抽样延迟，提交时只告知分布摘要，不泄露本次抽样值。以 game_fps=60×speed、delay_frames=ceil(delay_seconds×game_fps) 决定虚拟生效帧；端到端捕获/应用开销另按记录建模。

实际订阅计算可以比虚拟时间慢：当下一虚拟事件依赖尚未完成的订阅答案，协调器等待计算，然后继续相同虚拟时序。不能因真实 worker 慢而丢掉本应生效的动作，也不能提前使用返回答案。各轮记录实际墙钟、游戏时间和虚拟延迟。

先测原速模拟，再根据失败原因选 1/2、1/4、必要时 1/8；成功后逐档提速。速度、观测间隔和决策频率分开配置。原生逻辑 tick 始终是 60Hz，慢速仅改变逻辑帧与现实时间换算，不能改变子弹或移动的每帧数值。

串行无负载 profile 只能描述无负载 API 延迟；将其独立复制到多路可能乐观。开发至少加入 1.25×/2× 延迟、成段相关慢请求、漏请求等敏感性条件，明确标成压力假设，真实容量和限流效应留到最终 API 实测，不能称为已校准的并发性能。

6. 三层并发与同局多策略

| 层 | 初始方案 | 含义 |
| --- | --- | --- |
| 同时 episode 数 | 先 1 局验证，再 4–8 局 | 评估不同候选/seed |
| 每局实际订阅 worker | 先 1，再 3；起步总量 8×3=24 | 提升真实计算吞吐 |
| 每局目标虚拟容量 | 对比 1/4/8，必要时 16/24 | 模拟部署允许的在途请求 |

24 是起步吞吐目标，不是最佳容量结论。预检确认资源、订阅限流和调度正确后可扩大到 32/48 实际 worker；不能仅增加 worker 就宣称策略提升。已存在的 Asterix 进程、共享认证目录和结果不修改、不终止。

同一 episode 允许多个 Sol 策略从同一组可见截图提出候选，例如瞄准、避弹、保守走位三种提示。采用预先冻结的仲裁：首个合法候选，或有截止时间的多数票；两者分别作为实验条件。不能回看未来轨迹或引擎隐藏状态挑最好动作。

每个候选都占目标容量，分别计延迟和 API 成本。若用 Sol 做二次仲裁，额外请求及串行仲裁延迟也计入模型闭环。不得假定并发 K 个候选后仍只付一次延迟/成本。

7. 持续 autoresearch 循环

先完成最小视觉基线和固定/随机对照。每轮固定代码、prompt、输入、动作协议、调度、速度与全部 seed/延迟随机种子，然后运行完整局。主指标按通关数优先，其次未通关局剩余 Boss HP；辅助指标为存活时间、命中输出、被弹、剩余资源、动作年龄、陈旧响应比例与每游戏秒成本。

从死亡/未击破前的对齐截图和动作提出一个可验证假设，再优先改一项：

- 识别自机和 Boss、借助时间窗口推断弹幕运动；
- 在延迟期间的预判与提前释放，避免长按漂移和重复下发；
- 在安全位置维持火力，与 Boss 水平运动配合；
- 合理使用有限 X，而非只追求无伤或存活；
- 历史窗口、紧凑 prompt、短 chunk 和重规划频率；
- 单局并发候选与仲裁。

完整三开发 seed 才比较一轮结果；短 smoke 仅排错，不能作为通关率。挑出冠军后独立复跑，使用新的延迟随机数；再做压力测试。可用无关截图/固定动作消融检查闭环是否实际依赖视觉输入，但不能仅凭单一消融宣称严格因果证明。

协调器每轮输出采用/拒绝/复测及依据，随后继续下一项实验。在 session 内持续等待和跟进，不因短工具超时或一轮结束停止研究。订阅不设人为小额消耗上限，但尊重实际额度与限流；认证/额度耗尽时保存状态并暂停相关通道，禁止付费 fallback。

8. 冻结与真实 API 验证

冻结候选的完整配置，串行复测最终请求形状。按实测单请求成本、最大发送数、并发候选数、重试数和在途预留估算整局费用，在发出第一条请求前确认能覆盖计划验证。

先运行默认 seed=1 的原速完整 episode：真实 API 答案实际控制游戏，等待期间游戏照常推进。然后在剩余预算内按预注册顺序测试留出 seeds。对外分开报告一次通关、k/n 成功率、模拟稳定性和真实 API 稳定性。

最终保存原速录屏、模型输入截图及哈希、请求/动作/延迟/usage 日志、配置与引擎哈希。视频标明真实 API、原速或慢速、是否延迟模拟、以及该局在所有尝试中的位置。

真实验证失败时记录实际延迟、限流、动作年龄和失败轨迹，回订阅阶段修正。凡 policy 或控制协议改变，视为新候选，重新冻结确认；若预算不足，报告模拟已达成、真实验证未通过/未完成，不报 solved。

9. USD 30 累计预算

| 用途 | 上限预分配 |
| --- | ---: |
| 首轮严格串行 profiling | $6 |
| 最终请求形状串行复测 | $3 |
| 真实 API 完整试玩与验证 | $18 |
| 未返回 usage / 请求边界等缓冲 | $3 |
| 总额 | $30 |

预算是全实验累计，不能每进程/每次重启重置。已结算费用＋未知费用保守预留＋所有在途请求最坏成本，在新请求发出前必须不超过分配额度；常规主动支出控制在 $27，留下 $3 缓冲。预留必须覆盖实际图片 token 上界、缓存写入与完整 max_output_tokens（含 reasoning）。缓存命中不能作为批准在途请求的前提。

使用当前核对的官方 tier 价格，不硬套旧脚本；费用不依赖缓存会命中。对 usage 缺失、费用估算失配或模型/tier 不符立即停止新付费提交，保留保守预留，核对后再决定。付费重试也算累计消耗。预算守卫是实验侧保护，不冒充供应商账单硬限额；在途与未知用量未核清前不继续花费。

实际能承担几局由 profiling 后计算，不能在不知道图像 token 成本前承诺大量真实 API episodes。若预测不足，优先通过订阅把更低调用频率的候选做强，再复测，而非压缩验收或突破 $30。
