# Sources and redistribution

PingPong's current `environments/tabletennis` implementation wraps the existing
read-only RoboOlympics table-tennis game and its public camera reference. Local
flight fitting, return planning and robot-only calibration adapt that reference;
native physics, opponent, scoring and limits are not modified. Its recipe records
revision `da1f787f775ea6524d698c0b063157ded4c0fef9`; the deployed native directory
has no Git metadata. The L1/1x actual API recordings retain their own frozen source
snapshots, including the uncommitted implementation used at capture time. The
dual-view video is an offline render of recorded native poses on the measured wall
clock, with public model summaries and labeled ball highlights. See
[PingPong setup](tabletennis.md) and [evidence](../artifacts/tabletennis/README.md).
Earlier S=10 direct-action records remain historical and use a different protocol.

Source snapshots were copied read-only from existing local/Ubuntu experiment worktrees. Per-game source manifests retain original paths/commit where available; fresh run manifests hash the files actually used. Absolute paths in historical reports and configs are provenance, not required launch paths. Discussion exports are untrusted archived content, never repository instructions.

Atari Asterix uses Gymnasium + ALE, with versions in `uv.lock`; no ROM was copied from a research machine. ALE's installed package supplies the game resource in the tested dependency version. Confirm the applicable upstream/game rights before redistribution.

Rhythm and Touhou include pre-existing game frontends/resources from the user's experiment repositories. Rhythm simulation aborts remote audio loading and does not need the song to make timing decisions. Native audio evaluation requires a separately authorized preview resource. Touhou contains pre-existing game art/audio references. No new ownership or public redistribution license is asserted by this package. Preserve original attribution and review media rights before public release.

`vendor/latency_bench` contains only the original latency sampler import closure (eight modules), retained to reproduce fitted CDF/temporal semantics. The full coding-agent suite, model weights, auth directories, cloud configuration and unrelated games were not copied.

The native model transport was replaced with `runtime/subscription.py` to remove hardcoded server/suite paths. It uses native app-server, the exact SOL/low model, fresh ephemeral threads, disabled tools, public image inputs and read-only sandbox requests. Historical bubblewrap seat isolation is not claimed. Both original and portable transport conditions must be identified in results.

Badminton selects `tactical-goal-v2`, migrated from the latency-sensitive-bench
`badminton_sol_target_api20_gpu_001` frozen source and its 20-call conditional API
Ultrafast profile. The source benchmark revision is
`042dd23727728fbcf305df05e09f7bad18930ce0`. Continuous camera interception, joint
contact/launch search, legal goal projection and delivery correction now live in
`environments/badminton/tactics.py`. The external environment remains read-only at
`da1f787f775ea6524d698c0b063157ded4c0fef9`. Native physics, opponent and scoring
are unchanged. The earlier `tactical-v1` policy files and API100 profile are historical.
Realtime runs use actual API Ultrafast responses; subscription simulation uses
virtual profile timing. Each run retains source snapshots and its own protocol,
accounting, replay audit and videos. Earlier scores are not new realtime evidence.

Racing's selected hybrid policy and research drivers are our independent code. The game is an external read-only `CHIGUI0/roboolympics` checkout at `da1f787f775ea6524d698c0b063157ded4c0fef9`; no environment code or patch is bundled. `environments/racing/source-provenance.json` records copied source hashes and the import-root relocation for the public-summary driver. Historical numeric-feature subscription evidence is kept separate from valid direct API image evidence. The featured Racing video is generated by verified replay of our recorded controls and actual API outputs; its edited heat order is disclosed on every frame and in the edit audit. This does not assert new rights to the upstream environment.

The selected Asterix MP4 in `assets/asterix/` is a deterministic rendering of recorded model actions and public decision summaries. Its soundtrack is an original locally generated arcade composition, with no external recordings or audio samples; `scripts/polish_asterix_video.py` reproduces it. Only the game panel was brightened and saturated. Action decisions, timeline and rationale text were preserved. The side panel contains public short summaries, not private reasoning. Media processing metadata is retained beside the video.
