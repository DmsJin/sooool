## Timing lessons to preserve

Empirical inverse-CDF sampling still schedules delivery in virtual time. Asterix quantizes sampled delay to raw frames with `ceil(delay * virtual_fps)`; the controller then determines whether/when an eligible result is actually applied. Rhythm uses continuous virtual milliseconds and jointly samples RTT, screenshot age and transport rather than independently mixing marginals. Touhou must preserve joint candidate readiness and terminal occupancy.

Today's streaming implementation makes a second time explicit: **valid action JSON ready** versus **full response drained/accounted**. Delivering early must not release the request's slot or budget reservation while the stream is still running. New profiles need the correlated occupancy tail; historical completed-response profiles remain historical. Rhythm's streaming change passed local 68 and Ubuntu 66 offline checks in development, but its real API latency/score benefit was not measured by that change.

For moving environments, show GPT the full unfinished suffix of its own already-returned action plan. Overlapping observations and multiple unknown responses can move the actor between capture and application; higher action rate alone did not improve Touhou outcomes. Keep model output, installed action, actual application frame, dropped result, public observation clocks and replay evidence separate.
